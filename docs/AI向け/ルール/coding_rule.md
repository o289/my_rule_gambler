# コーディング規則

## TypeScriptの型安全性

- `any`を追加しない。型が不明な入力は`unknown`で受け取り、検証してから使用する。
- `@ts-ignore`、`@ts-nocheck`を追加しない。`@ts-expect-error`は意図した型エラーを検証する型テストに限り、理由を記載する。実装の型エラーを隠すためには使用しない。
- `as unknown as T`や`as any as T`など、型検査を回避する二重キャストを追加しない。
- 型アサーションや非nullアサーション（`!`）で未検証の値を安全とみなさない。型ガードや分岐で型と値を確認する。
- 外部入力、APIレスポンス、保存データは実行時に検証する。型注釈や型アサーションだけを検証の代わりにしない。
- `null`、`undefined`、存在しない配列要素を扱う場合は、その可能性を確認してから使用する。

## 非同期処理とエラー処理

- 未処理のPromiseを追加しない。`await`で完了を待つか、明示的なエラーハンドラーを付ける。
- 完了を待たない処理でも拒否時の処理を定義する。`void`を付けるだけで処理済みとみなさない。
- `async`関数をコールバックとして渡す場合は、呼び出し元がPromiseを扱うか確認し、扱わない場合は拒否を捕捉する。
- 空の`catch`や、失敗を成功として扱う処理を追加しない。エラーは必要な通知、復旧、または呼び出し元への伝播を行う。
- 捕捉したエラーの型は`unknown`として扱い、内容を確認してから参照する。

## ログ

- デバッグ用の`console.log`、`console.debug`、`console.trace`や`debugger`を追加しない。
- 運用上必要なログは、既存のロギング方式に従い、必要な情報だけを記録する。
- 秘密情報、認証情報、個人情報をログに出力しない。

## 検査と変更範囲

- TypeScriptの型検査、Lint、テストを通すために、検査設定を弱めたり、検査対象から除外したり、抑制コメントを追加したりしない。
- 変更に関係する型検査、Lint、テストが用意されている場合は実行し、失敗の原因を確認する。
- 既存の命名、モジュール構成、フォーマットに従い、対象の要件に必要な変更のみを行う。
