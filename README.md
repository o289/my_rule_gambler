# 脳汁ビュービューゲーム

## ゲームルール

基本ルールは、サイコロを振り、ボードの絵柄に合わせて左から順番に置き、列の最後のマスを埋めた人が得点するゲームです。

1. 自分の番になったら、通常5個のサイコロを振ります。
2. 出た絵柄と一致するマスにサイコロを置きます。
3. 各列は必ず左から順番に埋めます。途中を飛ばして置くことはできません。
4. 置ける場合は最低1個置きます。複数置いてもかまいません。
5. 残ったサイコロをもう一度振るか、自分の番を終了するか選びます。
6. 列の一番右のマスを埋めた人が、その列の得点を獲得します。

ある列が `♠ ♠ ♠ +50点` の状態なら、最後の1マスを埋めた人が50点を獲得します。前の人が左2マスを埋めていた場合も、列を完成させた人が精算します。

ゲーム全体の進行とルールの根拠、未確認の旧版細則については[ギャンブラールールブック](./ギャンブラールールブック.md)を参照してください。

```sh
npm ci
npm run dev
```

## アセット

生成AIで制作した高級カジノ系の素材を使います。黒・金・重厚感のある画面に、ジャックポット演出を用います。複数要素で使う素材は [`src/shared/assets/`](./src/shared/assets/) に置き、要素固有の演出素材は各 feature に置いています。

## 3Dダイスのデモ

宝石ダイスは [`src/features/dice/ui/3d/`](./src/features/dice/ui/3d/) の Three.js 表示に一本化しています。ダイス、ボード、エフェクト、カジノエントリーで宝石画像とフレームを共有します。独立した2D表示・モーション・デモはなく、エフェクトの停止演出も同じ3Dダイス形状、面テクスチャ、停止タイミングを使います。

プレビューを2つ以上のタブで開くと、同じルームのプレイヤーとして参加できます。別の卓を開く場合は `?preview=dice&room=table-a` のようにルーム名を指定します。最初に入ったプレイヤーが手番です。手番プレイヤーの **ROLL DICE** で各画面にトレイが開き、全ダイスが止まるまで **CONFIRM** は押せません。各参加者は自分の画面のトレイを閉じられ、手番プレイヤーの **CONFIRM** で共有盤面が配置段階に進みます。

確定した出目を選び、各行の左端の空きマスに同じ宝石を配置できます。通常は1個以上配置すると残ったダイスを REROLL できます。置けない場合や配置を終えた場合は END TURN で手番を渡します。配置済みのダイスは振り直しの対象から外れます。この共有盤面はデモで、正式ルールにある列得点、勝敗判定、全ボード進行は対象外です。

### 物理演算と同期

| 場所 | 役割 |
| --- | --- |
| `src/features/dice/model/geometry.ts` と `src/shared/contracts/dice.ts` | トレイ寸法、宝石の面、通信データの型と検証 |
| `src/features/dice/server/physics.ts` | Rapier の剛体・衝突・停止判定 |
| `src/platform/local-demo-servers/dice/server/roll-runner.ts`、`room.ts` | 物理ロールの進行、フレーム配信、ルームと手番管理 |
| `src/platform/local-demo-servers/dice/server/http.ts` | Hono、HTTP health、WebSocket 接続とメッセージ受信 |
| `src/features/dice/ui/3d/tray-scene.tsx` | 固定俯瞰のThree.jsトレイ、カップ、ダイス描画、受信間の補間 |
| `src/features/dice/ui/connection.ts` | 既存 WebSocket デモの接続、再接続、クライアント状態 |
| `src/features/dice/ui/main.tsx`、`monitor.tsx` | React の操作画面、確定した宝石と開発計測値 |

サーバーはRapierを120Hzまたは240Hzの固定刻みで進め、衝突時の跳ね返りや摩擦を計算します。ダイスの速度と回転が落ち着いたあと、最も上を向いた宝石面を結果として確定します。判別しにくい斜めの停止には最大2回の物理的な刺激を試し、制限に達した場合は最も上向きの面を一度だけ採用します。

サーバーはロールID、時刻、順序番号、各ダイスの位置・回転・停止状態を約60Hzで配信します。ブラウザは短い受信遅延を使ってフレームを補間し、確定後はサーバーの位置と向きを表示します。結果一覧は参加画面で共用します。物理衝突の強さに応じた音が鳴ります。カップの登場、面の発光、CONFIRMにも効果音があります。

切断時は保存した復帰情報で同じ参加者に戻ります。進行中は最新の姿勢、停止後は確定結果を表示し、手番プレイヤーが確認済みなら更新された盤面へ復帰します。全員が離れたルームは猶予期間後に片付けます。ローカルサーバーを再起動すると、デモのルームは初期化されます。

### 開発計測

`?preview=dice&dev=1&room=lab` で性能モニターを表示します。手番プレイヤーは次回の演算を120Hzまたは240Hz、新規ロールを1〜5個に指定できます。開発モードでは配置前の振り直しも試せます。振り直す個数はサーバーが管理する未配置分です。

物理ステップ数、送信頻度、処理時間、CPU負荷、描画FPSと停止までの時間を画面に表示します。CPUはサーバープロセス全体の計測で、未取得の値は「—」です。開発機能を無効にしてサーバーを起動するには `DICE_DEV=0` を指定します。

## ギャンブラーボードのデモ

ボードのマスと宝石を選んで配置・削除を試せます。得点を変えるには対象の行のマスを選び、操作欄の「行の得点」を編集して「更新」を押します。「得点演出を再生」で、その行と得点プレートが光ります。リセットするとサンプルの配置・得点・選択状態に戻ります。

盤面の列見出し、行、得点、初期配置・利用可否は [`src/dev/preview-data/sample-board.ts`](./src/dev/preview-data/sample-board.ts) で指定します。行・列のIDはそれぞれ一意にします。初期配置と配置不可の指定は、行の `cells` に列IDをキーとして記述します。この盤面はデモ用です。

| ファイル | 素材 |
| --- | --- |
| `src/shared/assets/board/obsidian.webp` | 暗く磨かれた黒曜石に暖色の鉱脈が走る背景 |
| `src/shared/assets/board/outer-frame.webp` | 透過した中央を持つ彫金の金枠 |
| `src/shared/assets/board/cell-inlay.webp` | 金縁と四つ葉の彫り模様が入った空マス |

得点の数字はHTMLテキストで表示します。選択・配置・得点演出はCSSで描画し、端末で視覚効果を減らす設定が有効な場合は、移動や拡大を抑えて色と明るさで状態を伝えます。

## ギャンブラーのエフェクトデモ

ダイス停止、宝石の配置、BIG WIN、COMEBACK、JACKPOT VICTORY、あと1マスで逆転、振り直しの一投を確認できます。別の演出を選ぶと前の演出を中断します。「スキップ」で結果へ進み、「リプレイ」で同じ条件を最初から再生します。「リセット」で初期状態に戻ります。

- **あと1マスで逆転** は、320点の PLAYER 1 がアメジストで残り1マスを埋めて100点を獲得し、390点の首位を抜く例です。ダイスの停止、対象マスの一度だけの発光、実際の配置と加点を経て、既存の COMEBACK に進みます。
- **振り直しの一投** は、未配置のダイスが1個ある状態から「続ける」を試します。「振り直しの結果」で「配置先あり」または「配置先なし」を選べます。前者は出目に合う各行の左端の空きマスが光り、後者は「配置できるマスなし」を表示して次の手番へ移ります。

再生条件は [`src/features/effects/model/effect-model.ts`](./src/features/effects/model/effect-model.ts) の `DEMO` と `EffectParams` で指定します。盤面の行ID・列IDをマスの指定に使います。プレビューでは `window.gamblerEffects` から操作できます。効果再生APIの利用例です。

```ts
playEffect('BIG_WIN', { playerName: 'PLAYER 1', points: 100 });
playEffect('ONE_CELL_COMEBACK', { gem: 'amethyst' });
playEffect('REROLL_THROW', { gem: 'diamond' });
```

再生時間の管理と表示は別モジュールです。追加の2演出はデモ用に出目を指定し、3Dダイスの停止通知から結果を表示します。3D描画が利用できない環境でも結果を表示します。ダイス停止演出では3Dダイスの停止に同期した視覚・音のキューを使います。宝石の透過画像、ボード、黒曜石、勝利紋章、飾り素材を共有または再利用します。文字と得点はHTML、光や動きはCSS・Web Animations API・Canvasで描画します。効果音はファイルではなくWeb Audio APIで合成し、視覚効果を減らす設定では強い閃光や大きな移動を省きます。

## 銀行・コイン取引のデモ

プレビューの操作パネルで「支払い」と「受け取り」を切り替え、取引額を10点単位で入力します。金額に合う実際のコインを、枚数が少ない組み合わせから選びます。例えば100点は100点金貨1枚、150点は100点と50点が1枚ずつ、70点は50点1枚と10点2枚です。受け取りの金貨はトレーに着地したときに現れます。

モード切替や「リセット」は入力額を維持して初期残高に戻します。「もう一度再生」は前回の方向と金額で再生し、「演出スキップ」は取引後の結果を表示します。取引が終わってから金額を変更し、同じモードで新しく開始するときも初期残高から試せます。

[`src/features/bank/application/bank-api.ts`](./src/features/bank/application/bank-api.ts) の `playBankTransaction()` で、プレイヤーから金庫への支払い（`withdraw`）と金庫からプレイヤーへの受け取り（`deposit`）を開始できます。プレビューのブラウザからは `window.gamblerBank.playBankTransaction()` として呼べます。

```ts
playBankTransaction({ type: 'deposit', playerId: 'player-1', amount: 100 });
```

呼び出しが受理されると `true` を返し、開始済みの取引がある状態では `false` を返します。取引額は正の10点単位で、送る側の所持コインを使って指定額を作れる必要があります。プレイヤーの初期残高は200点（100点1枚、50点1枚、10点5枚）、金庫は300点（100点2枚、50点1枚、10点5枚）です。初期在庫は [`src/features/bank/model/bank-model.ts`](./src/features/bank/model/bank-model.ts) で設定できます。

額面の数字はHTML、コイン表裏はWebP、金庫の回転ハンドルとコインの厚みはCSS、移動軌跡はCanvasで描画します。100点金貨の表面 [coin-100.webp](./src/shared/assets/bank/coin-100.webp) は、50点金貨を参考に王冠、翼の彫刻、二重の縁を加えて画像生成した420×420の透過WebPです。音はWeb Audio APIで合成しています。端末の視覚効果を減らす設定が有効な場合は、大きな回転・飛行を省き、取引と得点変化を表示します。

## VIPプレイヤー情報のデモ

盤面の上にある「VIP PLAYERS」でプレイヤー一覧を開きます。カードを選ぶと詳細に切り替わります。「戻る」で選択していたカードに戻り、「閉じる」やEscapeキーで盤面に戻れます。初期状態は4人で、PLAYER 1 が自分、PLAYER 2 が手番です。

盤面下の「テスト操作」で人数、手番、自分、得点を変更できます。「3秒後に次の手番へ」を押してからパネルを開くと、一覧を表示したまま手番の光が移る様子を確認できます。「通知を試す」は残高を変えずに、加点と失点の通知を表示します。得点を実際に減らす操作は0点までで、通知には減った分だけを表示します。

一覧は常に手番順です。順位は得点に基づき、同点は同順位とし、次の順位は同点の人数分を数えます（例：1位、1位、3位）。得点は50点・10点コインの合計で、デモの増減操作に合わせて額面別の枚数も更新します。

- [`src/features/players/model/player-data.ts`](./src/features/players/model/player-data.ts) にプレイヤーデータ、手番・自分の指定、順位計算、得点通知イベントがあります。
- `player-modal.tsx` はブラウザ標準のダイアログで表示とフォーカスを、`player-panels.tsx` は一覧・詳細・コイン内訳を管理します。
- ゴールドフレームと手番の光はCSS、選択カードの拡大・復帰はブラウザのアニメーション機能を使っています。視覚効果を減らす設定では、移動や周囲を流れる光を省きます。

## カジノ入場・VIPラウンジのデモ

入場と待機室だけを試せる独立サーバーです。ルートの `npm run dev` がサーバーも起動します。プレビューを2つ以上のタブで開き、同じルームに参加します。別の卓は `?preview=casino&room=table-a` で指定します。各タブで **ENTER CASINO** を押して着席し、**READY** を選びます。2〜6人全員の準備が揃うと、卓の中央に3・2・1が表示され、その後は「ゲーム開始」の表示で止まります。

| 場所 | 役割 |
| --- | --- |
| `src/features/casino-entry/ui/casino-flow.tsx`、`casino.css` | 黒金の入口、VIP卓、座席、READY、カウントダウン、完了表示 |
| `src/features/casino-entry/ui/casino-assets.ts`、`asset-loader.ts` | 初回の画像読み込み・デコード、進捗、失敗分の再試行 |
| `src/features/casino-entry/ui/connection.ts`、`src/shared/contracts/casino-entry.ts` | ローカル入場サーバーとの同期、時計の補正、復帰、退出 |
| `src/platform/local-demo-servers/casino-entry/server/room.ts`、`http.ts` | 入室、座席番号と準備状況、ゲーム開始条件の判定 |
| `sound.ts` | クリック操作後に再生できる扉の金属音 |

画面は読み込み完了後もボタンを押すまで閉じたままです。CSS 3Dの遠近法と左右の蝶番で扉を奥へ回転させ、開き切ってから卓を操作できます。端末の視覚効果を減らす設定に従い、回転などを省略します。

サーバーは2人以上が接続中で全員READYになったとき、約3秒後の共通開始時刻を送ります。各画面は往復時間から時計の差を補正し、その時刻から数字を表示します。開始時刻にサーバーが条件を再確認して一度だけ開始します。カウント中のREADY取消、参加、退出、切断で待機に戻ります。通常の待機中に未準備の人が退出し、必要人数が揃っていればカウントを始めます。HOSTは最初に入室した接続中の席です。

切断した席は約90秒間、番号とREADYを保持します。再接続できる間は読み込み後に待機室や開始済みの画面へ戻ります。「退出」は接続中なら席を即時解放し、通信が途切れている場合は猶予期間で解放します。ルームの状態は入場サーバー内に保持され、サーバーを再起動すると初期化されます。

## ソース構成

- `src/app/` — 6つの個別プレビュー
- `src/features/` — ダイス、ボード、エフェクト、プレイヤー、カジノエントリー、バンク
- `src/shared/assets/` — 共有素材
- `src/shared/contracts/` — ダイスとカジノ入場の既存メッセージ形式
- `src/platform/local-demo-servers/` — ローカルデモサーバーとWebSocket接続管理
- `src/dev/preview-data/` — デモ盤面などのサンプルデータ
- `src/dev/tests/` — 既存の要素別テストソース（新しいテスト環境の設定・実行は今回の範囲外）

各要素のソースは `src/features/<feature>/ui/` と `model/` を基本に分けています。既存のダイス物理は `src/features/dice/server/physics.ts` にあります。サンプル盤面と画面操作はデモ専用で、6要素間を通した正式なゲーム進行、得点処理、勝敗判定を実装するものではありません。
