# ギャンブラーゲーム

## ゲームルール

基本ルールは、サイコロを振り、ボードの絵柄に合わせて左から順番に置き、列の最後のマスを埋めた人が得点するゲームです。

1. 自分の番になったら、通常5個のサイコロを振ります。
2. 出た絵柄と一致するマスにサイコロを置きます。
3. 各列は必ず左から順番に埋めます。途中を飛ばして置くことはできません。
4. 置ける場合は最低1個置きます。複数置いてもかまいません。
5. 残ったサイコロをもう一度振るか、自分の番を終了するか選びます。
6. 列の一番右のマスを埋めた人が、その列の得点を獲得します。

このアプリでは、得点が500点以上になった時点で対戦を終了します。全員が500点未満で全マスが埋まると、得点を持ち越して次の盤面に進みます。

ある列が `♠ ♠ ♠ +50点` の状態なら、最後の1マスを埋めた人が50点を獲得します。前の人が左2マスを埋めていた場合も、列を完成させた人が精算します。

ゲーム全体の進行とルールの根拠、未確認の旧版細則については[ギャンブラールールブック](./ギャンブラールールブック.md)を参照してください。

## 開発環境

Node.js 22.18 以降、または24.11以降を使用します。ルートで依存関係をインストールし、Vite+ のアプリとローカル通信サーバーを起動します。

```sh
npm ci
npm run dev
```

通常入口は [http://127.0.0.1:5178/](http://127.0.0.1:5178/) です。カジノ入場後にルームを作成するか、ルームIDで参加します。VIPラウンジで全員がREADYを選ぶと、共通カウントダウン後に確定席順が表示され、「対戦へ進む」から同じルームのダイス画面へ移動します。開発用デモ一覧は [http://127.0.0.1:5178/?preview=list](http://127.0.0.1:5178/?preview=list) です。通常のルームIDは8桁の16進数です。ダイス単独プレビューは別の内部IDを使うため通常ルームと混ざりません。

## アセット

生成AIで制作した高級カジノ系の素材を使います。黒・金・重厚感のある画面に、ジャックポット演出を用います。複数要素で使う素材は [`src/shared/assets/`](./src/shared/assets/) に置き、要素固有の演出素材は各 feature に置いています。

## 3Dダイスのデモ

宝石ダイスは [`src/features/dice/ui/3d/`](./src/features/dice/ui/3d/) の Three.js 表示に一本化しています。ダイス、ボード、エフェクト、カジノエントリーで宝石画像とフレームを共有します。独立した2D表示・モーション・デモはなく、エフェクトの停止演出も同じ3Dダイス形状、面テクスチャ、停止タイミングを使います。

プレビューを2つ以上のタブで開くと、同じルーム名のプレイヤーとして参加できます。別の卓を開く場合は `?preview=dice&room=table-a` のようにルーム名を指定します。通常ルームID用の8桁16進数は予約されているため、プレビューでは `table-a` など別の名前を使ってください。最初に入ったプレイヤーが手番です。手番プレイヤーの **ROLL DICE** で各画面にトレイが開き、全ダイスが止まるまで **CONFIRM** は押せません。各参加者は自分の画面のトレイを閉じられ、手番プレイヤーの **CONFIRM** で共有盤面が配置段階に進みます。

確定した出目を選び、各行の左端の空きマスに同じ宝石を配置できます。通常は1個以上配置すると残ったダイスを REROLL できます。置けない場合や配置を終えた場合は END TURN で手番を渡します。配置済みのダイスは振り直しの対象から外れます。ゴールと指定宝石の並びはルーム作成時にサーバーが決め、再接続しても同じ配置に戻ります。この共有盤面では、得点チップの精算・勝敗判定・全ボード進行は行いません。

| `src/platform/local-demo-servers/dice/server/room-runtime.ts`、`roll-runner.ts` | Node依存のID・時計・物理ロール組み立て、4ms実行、フレーム配信 |

サーバーはRapierを120Hzまたは240Hzの固定刻みで進め、衝突時の跳ね返りや摩擦を計算します。ダイスの速度と回転が落ち着いたあと、最も上を向いた宝石面を結果として確定します。判別しにくい斜めの停止には最大2回の物理的な刺激を試し、制限に達した場合は最も上向きの面を一度だけ採用します。

サーバーはロールID、時刻、順序番号、各ダイスの位置・回転・停止状態を約60Hzで配信します。ブラウザは短い受信遅延を使ってフレームを補間し、確定後はサーバーの位置と向きを表示します。結果一覧は参加画面で共用します。物理衝突の強さに応じた音が鳴ります。カップの登場、面の発光、CONFIRMにも効果音があります。

切断時は保存した復帰情報で同じ参加者に戻ります。進行中は最新の姿勢、停止後は確定結果を表示し、手番プレイヤーが確認済みなら更新された盤面へ復帰します。全員が離れたルームは猶予期間後に片付けます。ローカルサーバーを再起動すると、デモのルームは初期化されます。

### 開発計測

`?preview=dice&dev=1&room=lab` で性能モニターを表示します。手番プレイヤーは次回の演算を120Hzまたは240Hz、新規ロールを1〜5個に指定できます。開発モードでは配置前の振り直しも試せます。振り直す個数はサーバーが管理する未配置分です。

物理ステップ数、送信頻度、処理時間、CPU負荷、描画FPSと停止までの時間を画面に表示します。CPUはサーバープロセス全体の計測で、未取得の値は「—」です。開発機能を無効にしてサーバーを起動するには `DICE_DEV=0` を指定します。

## ギャンブラーボードのデモ

空きマスに薄く表示された宝石が、そのマスに置ける出目です。各行は左端から順に埋めます。ゴールの得点は最後のマスの下に表示され、右側は配置できません。長い行ほど得点が高く、デモでは長さ1〜6に −10、+10、+20、+30、+50、+100 を割り当てます。

「新しい盤面」でゴールの並びを変え、「リセット」で今の盤面の初期状態に戻します。行のマスを選ぶと、宝石の取り除きや行の得点編集を試せます。

ランダム盤面の生成は [`src/features/board/model/goal-layout.ts`](./src/features/board/model/goal-layout.ts) にあります。固定の演出用盤面は [`src/dev/preview-data/sample-board.ts`](./src/dev/preview-data/sample-board.ts) です。行の `goalColumnId` はゴールの列、各マスの `requiredGem` は指定宝石、`gem` は初期配置済みの宝石です。行のゴール指定が省略されている場合は、その行で最後に使えるマスがゴールになります。

| ファイル | 素材 |
| --- | --- |
| `src/shared/assets/board/obsidian.webp` | 暗く磨かれた黒曜石に暖色の鉱脈が走る背景 |
| `src/shared/assets/board/outer-frame.webp` | 透過した中央を持つ彫金の金枠 |
| `src/shared/assets/board/cell-inlay.webp` | 金縁と四つ葉の彫り模様が入った空マス |

得点の数字はHTMLテキストで表示します。選択と配置はCSSで描画します。

## ギャンブラーのエフェクトデモ

宝石の配置、得点・失点、BIG WIN、COMEBACK、JACKPOT VICTORY、あと1マスで逆転、手番の切り替えを確認できます。得点・失点は同じビームと得点プレートで表示します。例えば+100点で順位が変動する例を選ぶと、得点表示、BIG WIN、COMEBACKの順で再生します。端末で視覚効果を減らす設定にも対応します。別の演出を選ぶと前の演出を中断します。「スキップ」で次の演出または結果へ進み、「リプレイ」で同じ条件を最初から再生します。「リセット」で初期状態に戻ります。

- **あと1マスで逆転** は、320点の PLAYER 1 がアメジストで残り1マスを埋めて100点を獲得し、390点の首位を抜く例です。ダイスの停止、対象マスの一度だけの発光、実際の配置と加点を経て、既存の COMEBACK に進みます。

再生条件の初期値は [`src/dev/preview-data/effect-turn.ts`](./src/dev/preview-data/effect-turn.ts) の `DEMO` にあります。盤面の行ID・列IDをマスの指定に使います。プレビューでは `window.gamblerEffects` から操作できます。効果再生APIの利用例です。

```ts
playEffect('BIG_WIN', { playerName: 'PLAYER 1', points: 100 });
playEffect('ONE_CELL_COMEBACK', { gem: 'amethyst' });
```

再生時間の管理と表示は別モジュールです。「あと1マスで逆転」はデモ用に出目を指定し、3Dダイスの停止通知から結果を表示します。3D描画が利用できない環境でも結果を表示します。通常の投擲から停止・出目の表示までは3Dダイス画面で確認できます。「確定した出目」から宝石を選び、光っているマスを押すと、配置確定時にそのマスで着地と発光の演出が再生されます。効果音はWeb Audio APIで合成し、視覚効果を減らす設定では強い閃光や大きな移動を省きます。

## 銀行・コイン取引のデモ

プレビューの操作パネルで「支払い」と「受け取り」を切り替え、取引額を10点単位で入力します。金額に合う実際のコインを、枚数が少ない組み合わせから選びます。例えば100点は100点金貨1枚、150点は100点と50点が1枚ずつ、70点は50点1枚と10点2枚です。受け取りの金貨はトレーに着地したときに現れます。

- **金貨を圧縮** は、10点金貨5枚を50点金貨1枚、50点金貨2枚を100点金貨1枚にまとめます。残高と余った金貨はそのままです。受け取りやお釣りの着地後も、必要枚数が揃えば自動で圧縮します。
- **70点を100点金貨で支払う** は、初期残高200点から100点金貨1枚を金庫へ送り、同じ金庫から10点金貨3枚を1枚ずつ受け取る例です。残高は200 → 100 → 110 → 120 → 130点の順に変わります。

モード切替や「リセット」は入力額を維持して初期残高に戻します。「もう一度再生」は前回の取引や圧縮を、同じ金貨の構成から再生します。「演出スキップ」はお釣りと圧縮を反映した結果を表示します。取引が終わってから金額を変更し、同じモードで新しく開始するときも初期残高から試せます。

[`src/features/bank/application/bank-api.ts`](./src/features/bank/application/bank-api.ts) の `playBankTransaction()` で、プレイヤーから金庫への支払い（`withdraw`）と金庫からプレイヤーへの受け取り（`deposit`）を開始できます。プレビューのブラウザからは `window.gamblerBank.playBankTransaction()` として呼べます。

```ts
playBankTransaction({ type: 'deposit', playerId: 'player-1', amount: 100 });
playBankTransaction({ type: 'withdraw', playerId: 'player-1', amount: 70, tender: 100 });
```

呼び出しが受理されると `true` を返し、開始済みの取引がある場合や圧縮中は `false` を返します。取引額は正の10点単位です。`tender` を指定した支払いでは、その額面1枚と、金庫に実在するお釣りを開始前に確認します。単独の圧縮は `window.gamblerBank.compress()` からも試せます。プレイヤーの初期残高は200点（100点1枚、50点1枚、10点5枚）、金庫は300点（100点2枚、50点1枚、10点5枚）です。初期在庫は [`src/dev/preview-data/bank-demo.ts`](./src/dev/preview-data/bank-demo.ts) で設定できます。

額面の数字はHTML、コイン表裏はWebP、金庫の回転ハンドルとコインの厚みはCSS、移動軌跡はCanvasで描画します。100点金貨の表面 [coin-100.webp](./src/shared/assets/bank/coin-100.webp) は、50点金貨を参考に王冠、翼の彫刻、二重の縁を加えて画像生成した420×420の透過WebPです。音はWeb Audio APIで合成しています。端末の視覚効果を減らす設定が有効な場合は、大きな回転・飛行を省き、取引と得点変化を表示します。

## VIPプレイヤー情報のデモ

盤面の上にある「VIP PLAYERS」でプレイヤー一覧を開きます。カードを選ぶと詳細に切り替わります。「戻る」で選択していたカードに戻り、「閉じる」やEscapeキーで盤面に戻れます。初期状態は4人で、PLAYER 1 が自分、PLAYER 2 が手番です。

盤面下の「テスト操作」で人数、手番、自分、得点を変更できます。「3秒後に次の手番へ」を押してからパネルを開くと、一覧を表示したまま手番の光が移る様子を確認できます。「通知を試す」は残高を変えずに、加点と失点の通知を表示します。得点を実際に減らす操作は0点までで、通知には減った分だけを表示します。

一覧は常に手番順です。順位は得点に基づき、同点は同順位とし、次の順位は同点の人数分を数えます（例：1位、1位、3位）。得点は50点・10点コインの合計で、デモの増減操作に合わせて額面別の枚数も更新します。

- [`src/features/players/model/player-data.ts`](./src/features/players/model/player-data.ts) にプレイヤーデータ、手番・自分の指定、順位計算、得点通知イベントがあります。
- `player-modal.tsx` はブラウザ標準のダイアログで表示とフォーカスを、`player-panels.tsx` は一覧・詳細・コイン内訳を管理します。
- ゴールドフレームと手番の光はCSS、選択カードの拡大・復帰はブラウザのアニメーション機能を使っています。視覚効果を減らす設定では、移動や周囲を流れる光を省きます。

## カジノ入場・VIPラウンジのデモ

通常入口と `?preview=casino` は同じ入場画面を使います。`npm run dev` は待機室とダイスの通信入口を一つのNodeプロセスで起動し、両方が同じルーム管理表を使います。複数人の動作を確認するには、次の手順で同じルームに入ります。

1. **ENTER CASINO** で入口の扉を開け、**ルーム作成** で名前を入力して **作成して入室** を選びます。
2. 待機室に表示された8文字のルームIDを共有します。別タブでは **ルーム参加** を選び、IDを入力して **IDで参加** を押します。入室後のURLも共有できます。招待リンクから開くと **ルーム参加** が選ばれ、IDが入力欄に入ります。
3. サーバーが入室を認めると、部屋の扉が解錠して開きます。IDの入力違い、満室、開始済みの場合は入力画面にエラーを表示します。待機室の **退出** では扉を閉じ、ルーム選択へ戻ります。
4. 2〜6人全員が **READY** を選ぶと、卓の中央に3・2・1が表示されます。開始時に固定された席順が表示されたら、参加者は **対戦へ進む** を選びます。招待された席順に含まれない人にはこのボタンは表示されません。

| 場所 | 役割 |
| --- | --- |
| `src/features/casino-entry/ui/casino-flow.tsx`、`room-chooser.tsx`、`casino-doors.tsx`、`casino.css` | 入場、ルーム選択、扉の開閉、VIP卓、座席、READY、カウントダウン、完了表示 |
| `src/features/casino-entry/ui/casino-assets.ts`、`asset-loader.ts` | 初回の画像読み込み・デコード、進捗、失敗分の再試行 |
| `src/features/casino-entry/ui/connection.ts`、`src/shared/contracts/casino-entry.ts` | ルーム作成・IDによる入室確認、同期、復帰、退出、開始席順の受け渡し |
| `src/platform/server/core/lobby.ts`、`participant-lifecycle.ts` | ランタイム非依存のREADY・カウント期限・開始席順・再接続期限判定 |
| `src/platform/server/core/room.ts`、`room-registry.ts`、`src/platform/local-demo-servers/start.ts` | 一つのRoom実体と管理表を共有し、待機室から対戦へ同じ参加者・秘密トークンを引き継ぐ |
| `src/platform/local-demo-servers/casino-entry/server/http.ts`、`dice/server/http.ts`、`src/platform/server/websocket.ts` | Node通信入口、プロトコル変換、共通WebSocket制御 |
| `sound.ts` | クリック操作後に再生できる扉の金属音 |

画面は読み込み完了後もボタンを押すまで閉じたままです。CSS 3Dの遠近法と左右の蝶番で入口と部屋の扉を奥へ回転させます。卓を操作できるのは部屋の扉が開き切ってからです。端末の視覚効果を減らす設定に従い、回転などを省略します。

サーバーは2人以上が接続中で全員READYになったとき、約3秒後の共通開始時刻を送ります。各画面は往復時間から時計の差を補正し、その時刻から数字を表示します。開始時刻にサーバーが条件を再確認して一度だけ開始します。カウント中のREADY取消、参加、退出、切断で待機に戻ります。通常の待機中に未準備の人が退出し、必要人数が揃っていればカウントを始めます。HOSTは最初に入室した接続中の席です。

切断した席は約90秒間、番号とREADYを保持します。再接続できる間は読み込み後に待機室や開始済みの画面へ戻ります。「退出」は接続中なら席を即時解放し、通信が途切れている場合は猶予期間で解放します。ローカルルーム状態はサーバーのメモリ内に保持し、再起動すると初期化されます。

進捗は実際に読み込み・デコードできた画像の割合です。再試行時は失敗分のみ読み直します。盤面や3Dダイス、BGMはカジノ入場デモには含まれません。

## ソース構成

- `src/app/` — 6つの個別プレビュー
- `src/features/` — ダイス、ボード、エフェクト、プレイヤー、カジノエントリー、バンク
- `src/shared/assets/` — 共有素材
- `src/shared/contracts/` — ダイスとカジノ入場の既存メッセージ形式
- `src/platform/server/core/` — ランタイム非依存のロビー、ダイス規則、参加者期限、固定ステップ処理
- `src/platform/server/websocket.ts` — Node サーバー共通の WebSocket 接続制御
- `src/platform/local-demo-servers/` — Node起動元とカジノ・ダイスの通信入口、物理ロール実行
- `src/dev/preview-data/` — デモ盤面などのサンプルデータ
- `src/dev/tests/` — 要素別・サーバー通信とcoreの回帰テスト

各要素のソースは `src/features/<feature>/ui/` と `model/` を基本に分けています。既存のダイス物理は `src/features/dice/server/physics.ts` にあります。サンプル盤面と画面操作はデモ専用で、6要素間を通した正式なゲーム進行、得点処理、勝敗判定を実装するものではありません。
